# Security

AgentForge is a single-user tool for a locally trusted operating system account. The API and Vite development server bind to loopback, validate HTTP Host and browser Origin, reject oversized requests, and expose bounded graphs and outputs. The approval reviewer is the local operator. Local filesystem and process access imply control of the workspace.

- HTTP nodes permit exact administrator-approved HTTPS hosts on port 443. All resolved addresses must be public and non-multicast. The outbound TLS connection uses a checked address with hostname validation. Each GET redirect is revalidated and loses its credential header. POST redirects are rejected. Browser extraction has a separate exact-domain allowlist. The browser receives capped HTML from the pinned transport and has scripts, service workers, downloads and resource requests disabled. A restrictive content policy blocks embedded resources and frames. Site authentication, JavaScript-rendered pages and anti-bot challenges are outside this static extraction contract.
- Input and artifact files use approved roots and simple names. Traversal, aliases, Windows device names and linked paths are rejected. The local account controls the approved folder and its permissions, including changes after validation.
- Secrets are supplied through backend environment variables with a reserved prefix. Ordinary APIs return reference names only. Sensitive field names and known secret values are redacted from persisted execution data. Workflow saves reject detected inline secrets. Secret detection is conservative and operators must avoid including sensitive data in ordinary values or URLs.
- AI task adapters scrub configured secret values and recognizable credential patterns before forming prompts. Returned text and JSON are validated as data, with no provider tools or command execution. Arbitrary sensitive business content may evade pattern matching. Review data before opting in to a remote model.
- Set `AGENTFORGE_SECRET_REVIEWER` for an explicit approval decision check. The browser keeps the entered key in memory. The endpoint compares it against the environment and records decisions without the key. Default loopback use trusts the local operator and processes running in that account.
- Webhook bodies have a one-megabyte limit, exact-byte timestamped authentication, signed event IDs, a five-minute timestamp window, and an accepted-event rate limit. Duplicate or expired approval decisions cannot resume a run again.
- Workflow conditions, field mapping, and local templates use bounded declarative inputs. The application includes no arbitrary Python, JavaScript, or shell node. Spreadsheet writers neutralize leading formula characters in text cells.
- Outbound POST is off by default. Enabling it requires an administrator option and a directly connected approved branch. A request that has left the process may complete after cancellation or a timeout. Review external activity before repeating a write.

Public or shared deployment requires identity and authorization, tenant scoping, secure artifact storage, enforced infrastructure egress, runtime isolation, centralized rate limiting, and secret rotation. The Compose options are for a loopback single-operator environment.
